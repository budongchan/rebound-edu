## 2. 주간 운영 루틴 (매주)

### 2-1. 새 회차 강의 등록 (회차 모델 완성 전까지 우회 방식)
`/teacher/courses/new`에서 다음 정보 입력해서 신규 강의 등록:
- 제목: "중개실무 라이브 — N회차 (날짜)"
- 카테고리: `brokerage` (중개업)
- 가격: 무료(0원) 또는 유료
- 설명: 일시·장소·줌링크·정원·신청마감 모두 기재
- 상태: `published` (또는 `review`→`approved`→`published`)

또는 Supabase SQL Editor에서:
```sql
INSERT INTO courses (instructor_id, title, subtitle, description, price, category, status, published_at)
VALUES (
  'a0000000-0000-0000-0000-000000000001',  -- 김동찬 강사 ID
  '중개실무 라이브 — 2회차 (6/2)',
  '매주 진행되는 중개사 대상 실무 교육 (2회차)',
  '일시: 2026-06-02 19:00~21:00\n장소: 줌 라이브 (링크 별도 발송)\n정원: 30명\n신청마감: 6/2 17:00',
  0, 'brokerage', 'published', now()
);
```

### 2-2. 수강신청 현황 확인
`/admin/users` 화면에서:
- 소속 필터 ("리바운드 중개사", "외부 중개사" 등)로 가입 사용자 구분
- 검색창에 이름·이메일·전화·소속명 모두 검색 가능

`/staff/students` 화면에서:
- 학생 DB + 수강 강의 수 확인

### 2-3. 미입력 사용자 확인
`/admin/users` → "미입력" 필터: 가입 후 추가정보 안 채운 사용자 확인
※ 시스템상 이 사용자는 어떤 보호경로(/student·teacher·staff·admin)에도 진입 불가. 자동 강제 입력 화면으로 이동됨.

## 3. 사용자 가입·수강 흐름 (UX)

```
1. 사용자가 edu.rebound.io.kr 접속
2. "로그인" 또는 "시작하기" 클릭
3. Google 로그인 → users 테이블 자동 생성
4. /auth/complete-profile로 자동 이동
   ▸ 이름·연락처·소속구분·소속명 입력 (필수)
   ▸ 지점·관심분야 입력 (선택)
   ▸ 약관 동의
5. 가입 완료 → /auth/select-role
6. 역할(고객) 클릭 → /student 대시보드 진입
7. /student/explore에서 강의 목록 확인 → 강의 클릭 → 수강 신청
   ▸ 무료 강의: 즉시 enrollments 등록
   ▸ 유료 강의: 토스페이먼츠 결제 또는 Cafe24 외부결제 분기
```

## 4. 자주 발생하는 이슈 대응

| 증상 | 원인 | 해결 |
|---|---|---|
| 로그인했는데 자꾸 추가정보 화면으로 감 | 소속/연락처/이름 중 1개라도 비어있음 | 사용자에게 완성 안내 |
| 수강신청 버튼 눌렀는데 결제 안 됨 | course의 status가 `published` 아님 | `/admin/approvals`에서 published로 변경 |
| Cafe24에서 결제했는데 수강 목록에 안 보임 | Cafe24 외부결제 자동 등록 미구현 | 운영자가 SQL Editor에서 수동 등록 (Phase B에서 자동화 예정) |
| 강의 등록했는데 강의 목록에 안 보임 | course.status가 published 아님 / published_at 비어있음 | 상태/날짜 수정 |

수동 enrollments 추가:
```sql
INSERT INTO enrollments (user_id, course_id, status, progress_pct)
VALUES (
  (SELECT id FROM users WHERE email = '대상자@gmail.com'),
  (SELECT id FROM courses WHERE title LIKE '중개실무%2회차%'),
  'active', 0
);
```
